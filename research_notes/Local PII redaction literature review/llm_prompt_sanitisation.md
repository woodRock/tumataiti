# Sanitising, redacting and pseudonymising prompts before cloud LLMs, and the risks that remain

Scope: client-side and local prompt sanitisation with restoration (rehydration), how utility is affected, what risk remains (attribute inference, re-identification, quasi-identifiers), DP text rewriting compared with redaction, privacy in RAG, and injection risks to rehydration. Notes were compiled 2026-11-04.

Verification legend. **[V]** means existence and bibliographic details were confirmed during this session from arXiv, the ACL Anthology, a publisher page or the vendor's own docs. **[V-title]** means only the title, ID and existence were confirmed from a search listing; the content was not read, so claims about it are kept to a minimum. **[Preprint]** means arXiv only, with no peer-reviewed venue confirmed. Works recalled from background knowledge but not verified this session are listed under Gaps, not cited as findings.

## Q1. Systems for client-side / local prompt sanitisation and pseudonymisation with restoration, and how they evaluate privacy and utility

### Takeaway
A clear lineage of "sanitise locally, query the cloud, restore locally" systems exists, all very close to Tūmataiti's design: HaS (2023), PP-TS (2023), Casper (2024/25), Rescriber (CHI 2025), PAPILLON (NAACL 2025), and a general pseudonymisation framework (2025). Alongside them sit representation-level methods (TextObfuscator, PrivacyRestore) and token-importance rewriting (ProSan). Evaluation is inconsistent across the field. Privacy is usually measured as a simulated attacker's recovery rate or "leak rate", and utility as task metrics or response similarity. No system is evaluated against quasi-identifier re-identification in small populations.

### Cited Findings

**Local hide/restore pipelines (closest to Tūmataiti)**
- **Chen, Y. et al. (2023). "Hide and Seek (HaS): A Lightweight Framework for Prompt Privacy Protection." arXiv:2309.03057. [V][Preprint]** Method: a small local "Hide" model anonymises private entities before the prompt goes to the cloud LLM, and a local "Seek" model restores the originals in the response. Training data is LLM-generated, and an off-the-shelf NER model can stand in for the hider. Evaluation: translation and classification tasks; privacy measured with black-box and white-box adversary models trained to "decrypt" hidden entities. The authors claim an "optimal balance" between privacy and utility. Relevance: the most direct prior art for Tūmataiti's hide-and-rehydrate design, and the only one here that trains an adversary specifically to invert the substitution. — [arXiv](https://arxiv.org/abs/2309.03057)
  - A separate product, xuanwulab's "HaS Text" 0.6B on-device anonymisation model with reversible restoration, is listed on Featherless. It is not the same artefact as the paper. — [Featherless model page](https://featherless.ai/models/xuanwulab/HaS_Text_0209_0.6B)
- **Kan, Z. et al. (2023). "Protecting User Privacy in Remote Conversational Systems: A Privacy-Preserving Framework based on Text Sanitization" (PP-TS). arXiv:2306.08223. [V][Preprint]** Method: a local LLaMA model runs multiple cycles of sanitisation to de-identify the request before sending it, then re-identifies and restores the originals in the remote LLM's response. Each privacy type has its own requirements and few-shot examples, with a reasonability check on output. Privacy is evaluated by simulated attack success rates, and an ablation without the privacy filter shows attacks succeeding far more often. — [arXiv](https://arxiv.org/abs/2306.08223)
- **Chong, C. J., Hou, C., Yao, Z., Seyed Talebi, S. M. (2024/2025). "Casper: Prompt Sanitization for Protecting User Privacy in Web-Based Large Language Models." arXiv:2408.07004; published at IEEE CSCloud 2025. [V]** Method: a browser extension that runs entirely on the device, with three layers: a rule-based filter, an ML NER model, and an in-browser local LLM that identifies privacy-sensitive *topics*. It needs no changes to the LLM service. Results in the published version: 92.6% PII filtering accuracy, 92.5–94.0% topic-detection accuracy, and 92.0% of sensitive items pseudonymised, on 4,500 synthetic plus 2,000 real prompts. Responses to sanitised prompts had only moderate cosine similarity to originals (0.538), which shows the utility cost. Relevance: the same deployment model as Tūmataiti, and the topic layer addresses sensitive content that is not a named entity. — [arXiv](https://arxiv.org/abs/2408.07004)
- **Zhou, J. et al. (2025). "Rescriber: Smaller-LLM-Powered User-Led Data Minimization for LLM-Based Chatbots." CHI 2025, DOI 10.1145/3706598.3713701; arXiv:2410.11876. [V]** Method: a Chrome extension that highlights personal information in prompts. The user chooses what to redact, and redacted spans used in the answer are swapped back to the originals. User studies were small (N=12). Users perceived a Llama3-8B backend as on par with GPT-4, and the tool reduced unnecessary disclosure. Relevance: human-in-the-loop UX evidence for a local redaction layer. — [arXiv](https://arxiv.org/abs/2410.11876)
- **Li, S., Chithrra Raghuram, V., Khattab, O., Hirschberg, J., Yu, Z. (2025). "PAPILLON: Privacy Preservation from Internet-based and Local Language Model Ensembles." NAACL 2025 (Long), pp. 3371–3390; ACL Anthology 2025.naacl-long.173; arXiv:2410.17127. [V]** Method: "privacy-conscious delegation", where a local model (Llama-3.1-8B) rewrites the request and queries GPT-4o-mini as a tool, with the pipeline optimised by DSPy prompt optimisation. Introduces the PUPA benchmark of real user–LLM conversations containing PII. Result: response quality preserved 85.5% of the time, with PII leaked 7.5% of the time. Relevance: shows that LLM rewriting rather than span substitution is a viable alternative, and gives a benchmark (PUPA) Tūmataiti could evaluate on. — [ACL Anthology](https://aclanthology.org/2025.naacl-long.173)
- **Hou, S., Shang, R., Long, Z., Fu, X., Chen, Y. (2025). "A General Pseudonymization Framework for Cloud-Based LLMs: Replacing Privacy Information in Controlled Text Generation." arXiv:2502.15233. [V][Preprint, "under review"]** Method: decomposes pseudonymisation into detection (DET: NER or LLM), surrogate generation (GEN: e.g. random), and replacement (REP: direct string substitution, or LLM-generated rewriting). Evaluated on QA, summarisation, generation, MNLI and MT. Per the paper's results (via search summary), DET_NER+GEN_rand+REP_direct was best for QA and summarisation, while detail-sensitive tasks (MNLI, MT) favoured REP_gen variants. Code is public. — [arXiv](https://arxiv.org/abs/2502.15233)

**Representation-level or rewriting approaches**
- **Zhou, X., Lu, Y. et al. (2023). "TextObfuscator: Making Pre-trained Language Model a Privacy Protector via Obfuscating Word Representations." Findings of ACL 2023, pp. 5459–5473; ACL Anthology 2023.findings-acl.337. [V]** Method: privacy-preserving *inference* in a split setting, where the client obfuscates token representations using random perturbations over clustered representations, so each word keeps its function while its identity is hidden. Requires cooperation from the model owner (white-box access), so it is not applicable to closed cloud APIs. — [ACL Anthology PDF](https://aclanthology.org/2023.findings-acl.337.pdf)
- **Zeng, Z. et al. (2024–25). "PrivacyRestore: Privacy-Preserving Inference in Large Language Models via Privacy Removal and Restoration." arXiv:2406.01394 (v1 June 2024; later revisions to 2025). [V][Preprint per arXiv listing]** Method: the client removes privacy spans. The server has pre-trained "restoration vectors" per privacy-span type and applies activation steering during inference to restore the information's effect without seeing the text. The LLM stays frozen and the method is plug-and-play. Evaluated on medical and legal datasets. Relevance: an alternative to text-level rehydration, but it needs server cooperation. — [arXiv](https://arxiv.org/abs/2406.01394)
- **Shen, X. et al. (2024). "The Fire Thief Is Also the Keeper: Balancing Usability and Privacy in Prompts" (ProSan). arXiv:2406.14318 (cs.CR). [V][Preprint]** Method: scores each word's task importance (via gradients of the loss on model output) and privacy risk, then replaces only words that are high-risk and low-importance, preserving readability. Results: removes private information across QA, summarisation and code generation with minimal task-performance loss. Relevance: replacement guided by *contextual* privacy rather than entity types. — [arXiv](https://arxiv.org/abs/2406.14318)

**DP token-level sanitisers (SanText family)**
- **Yue, X., Du, M., Wang, T., Li, Y., Sun, H., Chow, S. S. M. (2021). "Differential Privacy for Text Analytics via Natural Text Sanitization" (SanText/SanText+). Findings of ACL-IJCNLP 2021, pp. 3853–3866; ACL Anthology 2021.findings-acl.337. [V]** Method: token-level local DP that replaces each token with a token sampled according to embedding similarity, plus sanitisation-aware BERT pretraining. Notable claim: higher utility did not increase inference-attack success. — [ACL Anthology](https://preview.aclanthology.org/setup/2021.findings-acl.337)
- **Chen, S. et al. (2023). "A Customized Text Sanitization Mechanism with Differential Privacy" (CusText). Findings of ACL 2023, pp. 5747–5758; DOI 10.18653/v1/2023.findings-acl.355; arXiv:2207.01193. [V]** Method: an ε-DP mechanism (not metric-LDP) in which each input token gets a customised output set. It works with any similarity measure and claims better privacy–utility trade-offs than SanText. (A search aggregator listed the authors inconsistently; the first author per the Anthology reference is Sai Chen.) — [ACL Anthology PDF](https://aclanthology.org/2023.findings-acl.355.pdf)
- **[V-title][Preprint]** "Preempting Text Sanitization Utility in Resource-Constrained Privacy-Preserving LLM Interactions", arXiv:2411.11521, applies DP sanitisers to the LLM-interaction setting with a small local model predicting utility. — [arXiv](https://arxiv.org/pdf/2411.11521)
- **[V-title][Preprint]** "Protecting User Prompts Via Character-Level Differential Privacy", arXiv:2603.26032. Content not read. — [arXiv](https://arxiv.org/pdf/2603.26032)

**Survey**
- **Edemacu, K., Wu, X. (2025). "Privacy Preserving Prompt Engineering: A Survey." ACM Computing Surveys 57(10):1–36; DOI 10.1145/3729219; arXiv:2404.06001. [V]** Classifies privacy methods for ICL and prompting into non-DP (including prompt sanitisation), local DP, global DP, and other categories. A useful framing reference for the review. — [ACM DL](https://dl.acm.org/doi/10.1145/3729219); [arXiv](https://arxiv.org/abs/2404.06001)

**Open-source and commercial gateways**
- **OpenAI Privacy Filter (2026). openai/privacy-filter, Apache-2.0, Hugging Face/GitHub. [V, via secondary press; openai.com returned HTTP 403 to fetch]** A 1.5B-parameter model with about 50M active parameters (MoE). It is a bidirectional token classifier derived from a gpt-oss-like autoregressive checkpoint, with constrained (Viterbi/BIOES) span decoding and eight span categories (person, address, email, phone, URL, date, account numbers, secrets; secondary sources disagree slightly on the list). It reports F1 96% on PII-Masking-300k (P 94.04 / R 98.04), after OpenAI corrected annotation errors. It is explicitly "not an anonymization tool or a compliance certification", performance may vary across languages and domains, and human review is advised in legal, medical and financial workflows. It is framed as a preview for high-throughput redaction. Tūmataiti already uses it as teacher and baseline (`ml/src/tumataiti_ml/detectors/openai_privacy_filter.py`). — [OpenAI announcement](https://openai.com/index/introducing-openai-privacy-filter/); [Help Net Security, 2026-04-23](https://www.helpnetsecurity.com/2026/04/23/openai-privacy-filter-personally-identifiable-information/)
- **LLM Guard (Protect AI).** An open-source toolkit with an `Anonymize` input scanner and a matching `Deanonymize` output scanner that share a `Vault` holding the placeholder→original mapping. This is the canonical open-source "mask then unmask" gateway pattern. Details here come from secondary sources (Langfuse docs and a tutorial); verify against the llm-guard docs. — [Langfuse security docs](https://langfuse.com/docs/security/getting-started)
- **LiteLLM proxy Presidio guardrail.** Runs Microsoft Presidio as a `pre_call` guardrail (mask input) and a `post_call` guardrail (input and output), with optional unmasking of output. — [LiteLLM docs](https://docs.litellm.ai/docs/proxy/guardrails/pii_masking_v2.md)
- **Cloudflare Firewall for AI (beta).** Inspects JSON prompts using Presidio's NER on Workers AI and populates WAF fields (`LLM PII detected`, categories) so that rules can *block* prompts. It detects and blocks; it does not redact or restore. Cloudflare notes that regexes struggle with PII embedded in natural language. — [Cloudflare docs](https://developers.cloudflare.com/waf/detections/firewall-for-ai); [Cloudflare blog](https://blog.cloudflare.com/take-control-of-public-ai-application-security-with-cloudflare-firewall-for-ai/)

### Inferences
- Evaluation of the hide/restore systems (HaS, PP-TS, Casper, Hou et al.) usually uses entity-recall or attacker-recovery for privacy and BLEU, ROUGE, accuracy or cosine similarity for utility. None measures residual *inference* risk of the kind Staab et al. demonstrate (Q3), so a Tūmataiti evaluation that does would be a genuine contribution.
- Gateway products are mostly server-side (enterprise proxies). The literature on systems running on the user's device is small: HaS, Casper, Rescriber, PAPILLON.
- Methods like PrivacyRestore and TextObfuscator need cooperation from the model provider and do not fit Tūmataiti's "untrusted cloud API" threat model. They are best cited as contrast.

### Gaps
- Vendor docs were not fetched for Private AI (PrivateGPT), Nightfall, Lakera, Skyflow, Protecto or similar commercial "LLM firewalls"; any claims about them should be checked before citing.
- The openai.com announcement could not be fetched (403); the model card on Hugging Face should be read directly for the exact label set and intended-use wording.
- Peer-reviewed venues for HaS, ProSan, PP-TS and Hou et al. were not found; treat them as preprints.

## Q2. Utility impact of redaction/pseudonymisation on downstream LLM tasks; placeholder vs surrogate; consistency

### Takeaway
Evidence consistently shows that utility loss depends on the task. Loss is small on general reasoning, but severe on retrieval or RAG and on tasks that depend on entities (30–60 point drops on RGB). Reversible, entity-consistent pseudonymisation clearly beats irreversible redaction, and telling the model that the text is anonymised does not help. No study isolates typed placeholders against realistic surrogates in a controlled ablation.

### Cited Findings
- **Deußer, T., Hahnbück, M., Sparrenberg, L., Uelwer, T., Bauckhage, C., Sifa, R. (2026). "On the Impact of Anonymization on the Performance of Large Language Models." arXiv:2609.11335 (Sep 2026). [V][Preprint]** Five LLMs (including Qwen2.5-72B and GPT-4o-mini) on eleven benchmarks. Degradation is minimal on ARC, HellaSwag and IFEval but drops 30–60 percentage points on RGB (retrieval-augmented). TruthfulQA *improved*. The more capable models degraded the most. Reversible, uniqueness-preserving pseudonymisation significantly outperformed redaction, and prompting the model about the anonymisation gave no benefit. One example is that replacing amounts with `<MONETARYVALUE>` caused reasoning errors. Relevance: the most direct recent evidence for Tūmataiti's placeholder design. Numeric and date entities need care, since a placeholder destroys arithmetic. — [arXiv](https://arxiv.org/abs/2609.11335)
- **Yermilov, O., Raheja, V., Chernodub, A. (2023). "Privacy- and Utility-Preserving NLP with Anonymized Data: A Case Study of Pseudonymization." TrustNLP Workshop @ ACL 2023; ACL Anthology 2023.trustnlp-1.20; arXiv:2306.05561. [V]** Compares NER-based, seq2seq and LLM-based pseudonymisation on summarisation and classification. NER-based pseudonymisation gave the best summarisation results, while the LLM-based method made more edits and so altered the text more. (The author list is from background knowledge; confirm on the Anthology page.) — [ACL Anthology PDF](https://aclanthology.org/2023.trustnlp-1.20.pdf)
- **Hou et al. (2025), arXiv:2502.15233 [V][Preprint]** (see Q1). Direct replacement with random surrogates is best for QA and summarisation, while LLM-rewritten replacement is better for detail-sensitive MNLI and MT. — [arXiv](https://arxiv.org/abs/2502.15233)
- **Casper (Chong et al. 2025) [V]** reports only 0.538 mean cosine similarity between responses to sanitised and original prompts, a substantial semantic drift. — [arXiv](https://arxiv.org/abs/2408.07004)
- **PAPILLON (Li et al. 2025) [V]** reports quality preserved in 85.5% of cases, with a "large margin" still left to un-sanitised frontier-model quality. — [ACL Anthology](https://aclanthology.org/2025.naacl-long.173)
- **ProSan (Shen et al. 2024) [V][Preprint]** reports minimal loss on QA, summarisation and code by replacing only words that are low-importance and high-risk. — [arXiv](https://arxiv.org/abs/2406.14318)

### Inferences
- In the Deußer et al. finding, "entity uniqueness preserved" beats redaction. This supports Tūmataiti's *consistent, indexed* placeholders (e.g. `[PERSON_1]` used for every mention) over a single generic mask token.
- Placeholders versus realistic surrogates is a trade-off. Surrogates read more naturally to the model, but a surrogate that collides with a real entity, or that the model "reasons about" (gender, ethnicity, locale), can distort answers and make rehydration ambiguous. Typed placeholders are unambiguous to restore but break type-dependent reasoning, such as arithmetic on amounts or date intervals. This is inference; no controlled study was found.
- Using RAG with redacted retrieved context is the riskiest case for utility (the RGB result), which matters for Tūmataiti's RAG-context feature.

### Gaps
- No dedicated, controlled ablation of typed placeholder versus surrogate versus generalisation (e.g. "a town in Northland") on LLM tasks was found.
- No study of *consistency* failures, meaning the same entity mapped to different surrogates across turns or documents in multi-turn chat, was found.
- No study on non-English or Māori-language text (te reo Māori names and place names) was found.

## Q3. Residual risk: attribute inference, re-identification from redacted text, quasi-identifiers, adversarial evaluation of anonymisation

### Takeaway
Removing direct identifiers does not remove identifiability. LLMs infer personal attributes from writing style and context with near-human accuracy at a tiny fraction of the cost (Staab et al. 2024), and they now de-anonymise pseudonymous users at scale (Lermen et al., USENIX Security 2026). Classic results (Sweeney; Rocher et al.) show that a handful of quasi-identifiers single people out, and the effect is stronger in small populations. Adversarial, inference-based evaluation (TAB, LLM anonymisers, RUPTA) is the current best practice.

### Cited Findings
**LLM inference and de-anonymisation**
- **Staab, R., Vero, M., Balunović, M., Vechev, M. (2024). "Beyond Memorization: Violating Privacy via Inference with Large Language Models." ICLR 2024; arXiv:2310.07298. [V]** Built a dataset of real Reddit profiles (PersonalReddit). LLMs inferred location, income, sex and other attributes with up to 85% top-1 and 95.8% top-3 accuracy, at about 100× lower cost and 240× less time than humans. Text anonymisation and model alignment were "currently ineffective" against LLM inference. Relevance: the core residual-risk citation. A cloud LLM receiving Tūmataiti-redacted text can still infer *who* the user is from context. — [arXiv](https://arxiv.org/abs/2310.07298); [ICLR](https://iclr.cc/virtual/2024/poster/17964)
- **Staab, R., Vero, M., Balunović, M., Vechev, M. (2025). "Large Language Models are Advanced Anonymizers." ICLR 2025; arXiv:2402.13846. [V]** Adversarial anonymisation: an LLM adversary infers attributes, then an anonymiser LLM generalises or removes the cues, and the loop iterates. Evaluated on 13 LLMs over real and synthetic texts, it beats commercial anonymisers on both privacy and utility. Relevance: a template for an "attribute-inference adversary" evaluation of Tūmataiti, and a possible optional rewriting stage. — [ICLR proceedings](https://proceedings.iclr.cc/paper_files/paper/2025/hash/f478b2e8ad9ff0756bf5b79fb31c330f-Abstract-Conference.html); [arXiv](https://arxiv.org/abs/2402.13846)
- **Lermen, S., Paleka, D., Swanson, J., Aerni, M., Carlini, N., Tramèr, F. (2026). "Large-scale online deanonymization with LLMs." USENIX Security 2026, pp. 1947–1966; arXiv:2602.16800. [V]** An open-web agent re-identifies Hacker News users and Anthropic Interviewer participants from pseudonymous text. A closed-world pipeline (LLM feature extraction → embedding search → LLM verification) reaches up to 68% recall at 90% precision, against about 0% for the best non-LLM baseline. Relevance: the strongest current evidence that context alone re-identifies people even with no explicit PII. — [arXiv](https://arxiv.org/abs/2602.16800)
- **Nyffenegger, A., Stürmer, M., Niklaus, J. (2024). "Anonymity at Risk? Assessing Re-Identification Capabilities of Large Language Models in Court Decisions." Findings of NAACL 2024; ACL Anthology 2024.findings-naacl.157; arXiv:2308.11103. [V]** On Swiss Federal Supreme Court rulings, LLMs struggled to re-identify parties, but did well on anonymised Wikipedia text. Model size, input length and instruction tuning drove success. The authors judged the risk minimal *for now*. Relevance: a counterpoint showing risk depends on whether the target is in public, web-scale text. Small-community individuals are rarely on Wikipedia, but local news and social media may cover them. — [ACL Anthology](https://preview.aclanthology.org/naacl24-info/2024.findings-naacl.157); [arXiv](https://arxiv.org/abs/2308.11103)
- **Yang, T., Zhu, X., Gurevych, I. (2025). "Robust Utility-Preserving Text Anonymization Based on Large Language Models" (RUPTA). ACL 2025 (Long); ACL Anthology 2025.acl-long.1404; arXiv:2407.11770. [V]** An iterative LLM loop with a privacy evaluator (a re-identification attacker), a utility evaluator and an optimiser, which jointly optimises against LLM re-identification while preserving utility. — [ACL Anthology](https://aclanthology.org/2025.acl-long.1404)
- **[V-title][Preprint]** "IncogniText: Privacy-enhancing Conditional Text Anonymization via LLM-based Private Attribute Randomization", arXiv:2407.02956. It rewrites text so that an attacker infers a *wrong* attribute value. — [arXiv](https://arxiv.org/html/2407.02956v1)

**Benchmarks and evaluation methodology**
- **Pilán, I., Lison, P., Øvrelid, L., Papadopoulou, A., Sánchez, D., Batet, M. (2022). "The Text Anonymization Benchmark (TAB): A Dedicated Corpus and Evaluation Framework for Text Anonymization." Computational Linguistics 48(4):1053–1101; DOI 10.1162/coli_a_00458; arXiv:2202.00443. [V]** 1,268 ECHR court cases annotated for direct *and* quasi-identifiers, with masking decisions, and privacy metrics (entity-level recall weighted by identifier type) alongside utility metrics. Relevance: the standard benchmark that distinguishes direct identifiers from quasi-identifiers. Tūmataiti's evaluation should report TAB-style recall on quasi-identifiers separately. — [ACL Anthology](https://aclanthology.org/2022.cl-4.19); [arXiv](https://arxiv.org/abs/2202.00443)
- **[V-title][Preprint]** "A Survey on Current Trends and Recent Advances in Text Anonymization", arXiv:2508.21587. — [arXiv](https://arxiv.org/pdf/2508.21587)

**Quasi-identifiers and small populations**
- **Sweeney, L. (2002). "k-Anonymity: A Model for Protecting Privacy." International Journal of Uncertainty, Fuzziness and Knowledge-Based Systems 10(5):557–570. [V]** A release is k-anonymous if each person is indistinguishable from at least k−1 others on its quasi-identifiers. Re-identification remains possible unless deployment policies are followed. — [Data Privacy Lab](https://dataprivacylab.org/projects/kanonymity/); [PDF](https://eng.auburn.edu/~xzq0001/courses/comp7370/k-anonymity-2002.pdf)
- **Rocher, L., Hendrickx, J. M., de Montjoye, Y.-A. (2019). "Estimating the success of re-identifications in incomplete datasets using generative models." Nature Communications 10:3069; DOI 10.1038/s41467-019-10933-3. [V]** A copula model estimates that 99.98% of Americans would be correctly re-identified in any dataset using 15 demographic attributes. Sampling or incompleteness does not provide meaningful protection, and heavily sampled datasets are unlikely to meet the GDPR anonymisation standard. — [PMC](https://pmc.ncbi.nlm.nih.gov/articles/PMC6650473)

**Memorisation and PII leakage (adjacent)**
- **Lukas, N., Salem, A., Sim, R., Tople, S., Wutschitz, L., Zanella-Béguelin, S. (2023). "Analyzing Leakage of Personally Identifiable Information in Language Models." arXiv:2302.00539; IEEE S&P 2023 (venue widely cited; proceedings page not fetched). [V]** A taxonomy of PII leakage (extraction, reconstruction, inference). Attacks extract up to 10× more PII. Sentence-level DP reduces leakage but about 3% of PII sequences still leak, and NER-scrubbing training data does not eliminate leakage. Relevance: if prompts are logged and trained on, the PII they contain can later leak from the model; this motivates redacting before sending. — [arXiv](https://arxiv.org/abs/2302.00539)

### Inferences
- In a small community (e.g. a NZ town of a few thousand, or a specific iwi or hapū context), combinations such as occupation + town + age band + a rare event can be unique even after names are removed. Rocher et al.'s uniqueness argument, applied to free text, combined with Staab et al. and Lermen et al.'s LLM inference capability, means Tūmataiti's guarantee should be framed as *removing direct identifiers*, not as anonymisation.
- TAB's split between direct and quasi-identifiers maps naturally onto a tiered Tūmataiti policy: always mask direct identifiers, and optionally generalise quasi-identifiers (place → region, age → band), as Staab 2025 and RUPTA do.
- OpenAI's own disclaimer ("not an anonymization tool") points the same way, so this framing is also the industry position.

### Gaps
- No study found that measures re-identification specifically in small or Indigenous populations from *free text* (as opposed to tabular data). This is a gap Tūmataiti can name.
- Sweeney's widely quoted "87% of the US population is unique on ZIP + birth date + sex" (Sweeney 2000, "Simple Demographics Often Identify People Uniquely", CMU Data Privacy Working Paper 3) was **not verified** this session.
- Recalled but unverified: Patsakis & Lykousas (2023) "Man vs the machine in the struggle for effective text anonymisation in the age of large language models" (Scientific Reports; cited inside RUPTA's related work, so it exists, but details are unchecked); Manzanares-Salor, Sánchez & Lison (2024), an ML re-identification attack on anonymised documents (Data Mining and Knowledge Discovery); Morris et al. (2022) "Unsupervised Text Deidentification" (Findings of EMNLP); Lison et al. (2021) "Anonymisation Models for Text Data" (ACL 2021); Mireshghallah et al. (2024) ConfAIde (ICLR 2024). Verify before citing.

## Q4. Text anonymisation vs differential privacy for text; why redaction is not DP

### Takeaway
DP text methods (word-level metric-LDP such as SanText and CusText; document-level paraphrasing such as DP-Prompt) give formal guarantees, but word-level guarantees are weak or misleading in practice (Mattern et al. 2022), and document-level DP rewriting costs a lot of utility. Redaction gives no formal guarantee at all, because the output depends deterministically on non-redacted content. It is best framed as data minimisation of direct identifiers.

### Cited Findings
- **Mattern, J., Weggenmann, B., Kerschbaum, F. (2022). "The Limits of Word Level Differential Privacy." Findings of NAACL 2022, pp. 867–881; DOI 10.18653/v1/2022.findings-naacl.65; arXiv:2205.02130. [V]** Shows "significant mathematical constraints diminishing the theoretical privacy guarantee" of word-embedding-perturbation DP, and practical failure against de-anonymisation attacks. Proposes document-level paraphrasing (fine-tuned GPT-2) as an alternative. — [ACL Anthology](https://preview.aclanthology.org/watermark/2022.findings-naacl.65); [arXiv](https://arxiv.org/abs/2205.02130)
- **Utpala, S., Hooker, S., Chen, P.-Y. (2023). "Locally Differentially Private Document Generation Using Zero Shot Prompting" (DP-Prompt). Findings of EMNLP 2023, pp. 8442–8457; ACL Anthology 2023.findings-emnlp.566; arXiv:2310.16111. [V]** Zero-shot LLM paraphrasing in which the privacy level is controlled by sampling temperature, which gives an ε-LDP guarantee through the bounded-logit exponential mechanism. Targets authorship de-anonymisation while limiting utility loss. — [arXiv](https://arxiv.org/abs/2310.16111)
- **Yue et al. 2021 (SanText) [V]** and **Chen et al. 2023 (CusText) [V]**: token-level DP sanitisers (see Q1).
- **[V-title][Preprint]** "A Comparative Analysis of Word-Level Metric Differential Privacy: Benchmarking the Privacy-Utility Trade-off", arXiv:2404.03324. — [arXiv](https://arxiv.org/pdf/2404.03324)
- **[V-title][Preprint]** "Spend Your Budget Wisely: Towards an Intelligent Distribution of the Privacy Budget in Differentially Private Text Rewriting", arXiv:2503.22379. — [arXiv](https://arxiv.org/pdf/2503.22379)
- **[V-title][Preprint]** "Thinking Outside of the Differential Privacy Box: …", arXiv:2410.00751, which evaluates text privatisation beyond DP framing. — [arXiv](https://arxiv.org/html/2410.00751v1)
- IncogniText's authors note that DP rewriting approaches carry high utility loss compared with LLM anonymisation. — [arXiv 2407.02956](https://arxiv.org/html/2407.02956v1)
- Lukas et al. (2023) show that even sentence-level DP training leaves about 3% PII leakage, i.e. the ε setting matters. — [arXiv](https://arxiv.org/abs/2302.00539)

### Inferences
- Redaction is not DP. A deterministic span-replacement mechanism M has outputs M(x) and M(x') that differ with probability 1 whenever x and x' differ outside the detected spans, so no finite ε bounds it. Detector misses (false negatives) pass through verbatim. Tūmataiti should therefore describe its guarantee in terms of *detector recall* plus *residual-inference evaluation*, not ε.
- Tūmataiti's rehydration requirement also conflicts with DP rewriting. A DP paraphrase cannot be mapped back exactly, which is one reason the restoration-based systems (HaS, PP-TS, Casper) all use deterministic substitution.

### Gaps
- Habernal (2021) "When differential privacy meets NLP: The devil is in the detail" (EMNLP 2021) and Feyisetan et al. (2020) "Privacy- and Utility-Preserving Textual Analysis via Calibrated Multivariate Perturbations" (WSDM 2020) are foundational, but neither was verified this session.
- No paper was found that formally argues "redaction ≠ DP" as its main thesis. The argument appears implicitly in Mattern et al. and the DP-NLP literature; the deduction above is my own.

## Q5. Privacy in RAG pipelines

### Takeaway
RAG creates a second leakage channel. Retrieved private documents can be extracted verbatim through crafted queries (Zeng et al. 2024; RAG-Thief; backdoors), and retrieval also changes memorisation behaviour. Proposed mitigations include synthetic replacement of the corpus, privacy-aware decoding, and sanitising the corpus. For Tūmataiti the threat model is different: the cloud LLM *sees* the retrieved context, so local sanitisation of retrieved chunks before sending is what matters.

### Cited Findings
- **Zeng, S. et al. (2024). "The Good and The Bad: Exploring Privacy Issues in Retrieval-Augmented Generation (RAG)." Findings of ACL 2024; ACL Anthology 2024.findings-acl.267; arXiv:2402.16893. [V]** Black-box attackers can extract data from the retrieval database with targeted and untargeted structured queries. RAG can also *reduce* leakage of the LLM's training data. — [ACL Anthology](https://aclanthology.org/2024.findings-acl.267/)
- **Zeng, S. et al. (2024). "Mitigating the Privacy Issues in Retrieval-Augmented Generation (RAG) via Pure Synthetic Data." arXiv:2406.14773. [V-title][Preprint]** Replaces the retrieval corpus with privacy-preserving synthetic data, evaluated with the attacks from the paper above. — [alphaXiv](https://www.alphaxiv.org/abs/2406.14773)
- **[V-title][Preprint]** "RAG-Thief: Scalable Extraction of Private Data from Retrieval-Augmented Generation Applications with Agent-based Attacks", arXiv:2411.14110. — [arXiv](https://arxiv.org/html/2411.14110v1)
- **[V-title][Preprint]** "Data Extraction Attacks in Retrieval-Augmented Generation via Backdoors", arXiv:2411.01705. — [arXiv](https://arxiv.org/pdf/2411.01705)
- **[V-title][Preprint]** "Privacy-Aware Decoding: Mitigating Privacy Leakage of Large Language Models in Retrieval-Augmented Generation", arXiv:2508.03098. — [arXiv](https://arxiv.org/pdf/2508.03098)
- **[V-title][Preprint]** "Exposing Privacy Risks in Graph Retrieval-Augmented Generation", arXiv:2508.17222. — [alphaXiv](https://www.alphaxiv.org/abs/2508.17222)
- **[V-title][Preprint]** "RAG Security and Privacy: Formalizing the Threat Model and Attack Surface", arXiv:2509.20324. — [arXiv](https://arxiv.org/pdf/2509.20324)
- Deußer et al. (2026): pseudonymisation causes 30–60 point drops on the RGB RAG benchmark. — [arXiv](https://arxiv.org/abs/2609.11335)

### Inferences
- Most RAG privacy papers assume a *trusted* LLM and a malicious *querier*. Tūmataiti's threat model (an untrusted LLM provider receiving retrieved chunks) is under-studied. The closest work is the prompt-sanitisation line (Q1) applied chunk by chunk.
- Entity mappings must stay consistent across the query *and* every retrieved chunk in one request. Otherwise the LLM cannot link "[PERSON_1]" in the question to the same person in a document. This is an engineering requirement that follows from the RGB utility result.

### Gaps
- No paper evaluating local, client-side sanitisation of RAG context sent to a third-party LLM, with restoration, was found.

## Q6. Prompt-injection / placeholder-injection risks for rehydration

### Takeaway
No peer-reviewed or preprint work was found that specifically studies attacks on placeholder rehydration: for example, an attacker-controlled document or model output emitting `[PERSON_2]` to make the client splice another person's real value into a visible or exfiltrated location, or injected instructions telling the LLM to reconstruct masked values. This appears to be an open gap. Adjacent literature covers indirect prompt injection generally and LLM de-anonymisation.

### Cited Findings
- A targeted search for injection attacks on pseudonymisation/restoration proxies returned no specific paper. The closest results were HaS's adversary models (which try to invert the hiding, not inject placeholders) and LLM de-anonymisation work. — [HaS arXiv](https://arxiv.org/abs/2309.03057); [Lermen et al.](https://arxiv.org/abs/2602.16800)
- LLM Guard's Anonymize/Deanonymize design keeps the mapping in a local `Vault`, and Deanonymize rewrites any placeholder found in the output. By construction, a placeholder string appearing in model output is substituted whatever its provenance. This is a design observation from the docs pattern, not a published attack. — [Langfuse docs](https://langfuse.com/docs/security/getting-started)

### Inferences (threat sketches for Tūmataiti; not from literature)
- **Placeholder injection / confused deputy.** Untrusted content in the prompt or RAG context (a web page, email or document) can contain literal tokens like `[EMAIL_1]`. If the model echoes them, rehydration may write the user's real value into, say, a drafted email to an attacker, or into a markdown image URL (an exfiltration channel). Mitigations: placeholder tokens that are random per session and unguessable (HMAC-style), escaping or rejecting placeholder-shaped strings in inbound text, and rehydrating only into display contexts, never into URLs, tool-call arguments or code that executes.
- **Reconstruction by inference.** Injected instructions ("what is [PERSON_1]'s likely real name given the context?") turn the cloud LLM into the Staab/Lermen-style inference adversary. Redaction cannot prevent this; it is the residual risk from Q3.
- **Mapping store.** Placeholder mappings are pseudonymisation under GDPR or NZ Privacy Act framing, and the local vault is the key secret to protect.

### Gaps
- No academic source was found on placeholder-injection or rehydration attacks. Greshake, K., Abdelnabi, S., Mishra, S., Endres, C., Holz, T., Fritz, M. (2023), "Not What You've Signed Up For: Compromising Real-World LLM-Integrated Applications with Indirect Prompt Injection" (AISec '23; arXiv:2302.12173), is the standard indirect-prompt-injection citation, but it was **not verified** this session (the search did not return it). Verify before citing.
- An industry write-up on "markdown image exfiltration" of chat data (e.g. by Johann Rehberger) is relevant, but no sources were collected.
